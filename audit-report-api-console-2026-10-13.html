F1 · 密码“留空不修改”实际清空密码，空口令可访问管理 API

HighConfirmed
主维度：security问题置信度：High影响范围：配置保存 → 管理认证
问题

空字符串被当成新密码发布到运行时。启动时生成随机密码的保护没有覆盖热更新入口；Basic Auth 分支也没有要求配置密码非空。

web/templates/pages/config.html:77：密码输入提示“留空则不修改”。 web/static/js/config.js:265：无条件提交 admin_password。 internal/api/api_config.go:185、302–330：buildConfigFromPatch 覆盖 admin_pass；persistConfig 仅 ApplyHardcoded，不拒绝空密码。 internal/middleware/session.go:244–246：SessionAuthDynamic 对 Basic Auth 的口令与空 adminPass 比较并放行。 本地复现 TestAuditBlankPasswordAndTokenLoss：保存空值后，无 Cookie、任意用户名、空密码的受保护请求进入 handler（204）。

用户影响：管理员正常操作即可意外关闭管理口令保护；随后能访问管理端口的未授权调用方可读取配置、导出账号或执行其他管理操作。

触发条件与失败过程：前置条件：管理员按页面提示清空密码输入框并保存，且管理 API 对攻击者可达。配置保存成功后，攻击者发送空密码 Basic Auth 即可通过认证。此次审计没有在生产环境执行该操作。

最小修复
后端将省略或空白密码解释为保留当前密码；若支持清除，必须显式禁止管理员密码清除。认证层额外拒绝空配置口令。前端空值不提交，三处语义保持一致。

回归验证建议：集成测试：从已设置密码的配置提交空字符串、空白、null 和省略字段；确认旧密码不变且空 Basic Auth 始终返回 401。使用实际配置保存与认证中间件串联验证。

工作量估计：0.5–1 天，含配置与认证回归。

F2 · 超过 8 MiB 的合法请求可绕过已耗尽的费用预算

HighConfirmed
主维度：cost问题置信度：High影响范围：推理费用预留 / 请求体边界
问题

费用检查和推理解析的正文上限不同。攻击者可以控制字段位置，让估算器看不到本来可定价的 model，而推理层仍能正常读取它。

internal/middleware/billing.go:30、208–218、279–298：readBillingBody 仅提供 8 MiB 前缀给估算器；不能定价则直接 next；完整正文仍交给推理 handler。 internal/pricing/pricing.go:126–133：前缀未读到 model 时返回未定价。 internal/httpserver/body.go:14：JSON 推理读取上限为 32 MiB；internal/handler/handler.go:162、286：共享 handler 上限为 50 MiB。 TestAuditLargeBodyBudgetBypass：在 model 前放置超过 8 MiB 的 JSON 空白，已耗尽预算的 Key 仍进入 handler，完整 JSON 可解码，且没有预留。

用户影响：配置了消费上限的 Key 可继续发起付费推理；请求没有 BillingReservation，后续结算也不会更新该 Key 的账本。默认不限额 Key 不属于此问题的触发对象。

触发条件与失败过程：前置条件：持有有效但预算已耗尽的 Key、允许使用可定价模型。向支持的推理路径发送 8–32 MiB 的合法 JSON，将 model 放在估算前缀之后。空白可在解析后消失，因此无须真的向上游发送超大提示词。

最小修复
