# 故障排查

## 1. 先确定失败层次

记录时间、路径、模型、request ID、HTTP 状态、最终 SSE 状态与错误码。按“入口 → 存储 → 账号选择 → 上游尝试 → 协议输出”定位，不用一次 429 推断所有账号都没额度。

## 2. 无法启动

| 现象 | 检查 |
|---|---|
| 找不到配置 | 当前工作目录与 -config，JSON / YAML 文件是否存在 |
| 配置解析失败 | 字段类型、JSON 语法；YAML 只支持扁平格式 |
| Redis 连接失败 | 地址、端口、密码、DB、网络与 Redis 日志 |
| 凭据解密失败 | 实际主密钥来源、Redis 与密钥是否同一备份 |
| 端口被占用 | 已有进程、systemd 与启动参数 |
| 前台运行正常、服务失败 | WorkingDirectory、ExecStart、用户权限及环境变量 |

不要删除密钥“让程序重新生成”来解决已有密文解密失败。先恢复原有效密钥。

## 3. 管理登录异常

空 admin_pass 可能在日志生成密码；Redis 保存配置也可能覆盖文件。客户端必须允许 session_token cookie，反向代理正确传递 HTTPS 协议，可信代理设置要匹配。

管理登录成功不意味着推理客户端已认证；管理员 cookie 与 API Key 是不同身份。创建 Key 后只显示一次完整秘密，列表掩码不能复制用于推理。

## 4. 模型目录为空或过时

1. 检查账号启用、凭据及最近授权状态。
2. 手动按通道刷新，区分 skipped、失败和成功。
3. 检查该通道上游目录 endpoint 与账号区域。
4. 检查模型是否禁用 / 不可见 / 权限不匹配。
5. 阅读目录同步时间与失败日志，避免旧快照当实时证明。

无活跃账号时不发布内置兜底目录。Cline 免费账号发布免费推荐列表，确认付费套餐后自动加入 ClinePass 模型；手工刷新账号或模型目录可立即重新观察套餐，后台也会按既有周期同步。Grok 目录过滤不支持的媒体标识。添加 API Key 不能让无账号的通道自动获得模型。

## 5. 401 / 403

先分辨网关入口身份失败与上游凭据失败。入口检查 Authorization / x-api-key、Key 过期、模型白名单；上游检查 OAuth refresh、身份头、账号区域及是否需重新授权。

Qoder 队列业务码可能在认证 HTTP 外壳里，程序按业务原因分类；不能仅看到上游 401 就反复删除账号。普通 Grok 403 也不等同账号封禁。

## 6. 402 / 429 / 503

| 原因 | 处理 |
|---|---|
| Key 预算不足 | 检查费用上限、预留和账期，必要时调整策略 |
| Key RPM / 并发 | 检查该 Key 限制和运行请求 |
| 账号额度耗尽 | 区分付费额度与仍可用免费模型，不补造余额 |
| 账号 / 进程 / 通道并发满 | 查看对应层限额，不能只提高其中一个 |
| Qoder 共享排队 | 按上游等待提示及预算重试，不靠无意义切号规避全局闸门 |
| 模型冷却 / 权益缺失 | 看模型范围原因，换模型或补有权益账号 |
| Redis 或上游不可用 | 看存储健康和网络尝试，区别真实零流量 |

Retry-After 是建议窗口，不保证下一次成功。等待预算也不能延长边缘代理自身超时。

## 7. 流式截断和超时

检查 EOF 前是否有协议终止、是否已经写出部分数据、工具参数 JSON 是否完成。代理缓冲、客户端断开、上游空闲、总期限和下游写期限分别可能结束请求。

`408 timeout` 且文案为 `request body read timed out` 表示网关在上传阶段没有及时读完请求体，尚未开始上游生成。请求体读取期限为 30 秒，与生成期限不同；检查客户端上传、代理连接和是否能在重试后恢复。此前版本将这类读取超时也返回为 `400 invalid json`，因此须结合请求耗时、诊断中的请求体及上游尝试数判断，不能仅凭旧错误文案归咎于模型或 JSON 格式。

Responses 的 `incomplete_details.reason=max_output_tokens` 表示该轮输出预算耗尽，推理也可能消耗全部预算，不能仅凭客户端的“stream disconnected”文案判断网络故障。核对同一 request ID 的实际上游预算、用量和终止事件；只有 `context canceled` 且尚未收到上游响应的记录不能证明 Token 触顶。WorkBuddy 未指定预算时自动使用所选账号上游模型目录公布的上限，缺少有效观察时不发送 `max_tokens`，采用上游默认行为；显式预算继续优先，真实截断仍返回 incomplete。

Grok keepalive 不算有效生成，语义空闲仍可触发；重复生成文本本身不再因次数中止。若重复输出仍结束，应查实际 stop、输出预算、质量策略、上游结束和超时。

sequence_number 只表示事件顺序；不要用 Last-Event-ID 假定网关自动续传。生成请求重发可能产生第二次真实消费，尤其工具轮次须确认重放安全。

## 8. 结构化输出失败

strict:true 下 schema_mismatch 说明受支持校验规则未通过，不是 Key 错误。查看原始模型输出、提取 JSON 和实际 schema；未知规则可能不被完整验证，不能因为成功就宣称任意 schema 全合规。

不支持的工具、include、text 控制可能在上游前返回 400。按能力矩阵调整请求，不以删除所有控制字段掩盖客户端需求。

## 9. Responses 资源与压缩失效

检查相同 Key、模型、入口渠道、TTL 和共享 Redis。跨 Key 404 是所有权保护；旧记录缺 input_items 返回空列表不是新一轮输入被删除。

bridge_compact_v1 是存储引用，不能移到另一网关。Grok 密封状态需要同一主密钥派生能力，改加密域或更换主密钥会影响历史。cancel 不承诺上游生成已停止。

## 10. 指标“全部为零”或日志找不到

先看聚合是否 available、查询是否报错、队列 dropped / write_failed 和时间范围。查看保留覆盖与分页扫描限制，再判断数据不存在。runtime 是当前副本，日志使用服务端 request ID 关联尝试。

缺 TTFT 不补零；采样不足时分位数不代表完整流量。重启后采集计数归零，不等同历史无失败。

## 11. 在线升级异常

检查能力原因、目标发行完整资产、MainPID / ExecStart、目录权限、启用环境和持久服务。操作中网络中断先查 operation，不重复 POST。recovery_failed 按 [恢复步骤](online-upgrade.md) 核对备份，禁止直接清 Redis。

## 12. 有效问题报告

提供：代码 / 运行版本与 commit、平台、路径与模型、错误码和 request ID、脱敏最小请求、是否流式、终止事件、发生时间与时区、相关采集健康。隐藏 Key、cookie、OAuth token、代理密码和账号导出内容。说明结果来自本地 mock、隔离真实上游还是生产，避免混淆。
