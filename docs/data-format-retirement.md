# 持久数据格式退役

本次精简不在启动时迁移、清空或重写 Redis。历史记录保留原字节，读取使用以下当前合同。

- 模型状态只接受 `available`、`maintenance`、`offline`。布尔值、旧别名、大小写变体及未知值均按离线处理。管理员显式保存状态或执行模型刷新后，写入当前格式；刷新保留已有可识别的状态，不自动启用离线模型。
- WorkBuddy、Cline 和模型发现读取的账号目录只接受当前 JSON 行。旧裸模型 ID 不再提供模型能力、窗口或免费权益。通过账号检查或显式刷新模型目录，从上游重新建立快照；刷新失败保留历史记录，部分账号失败时不裁剪已有模型。Grok 当前 `GrokModels` 的 ID 列表仍然有效。
- Grok 持久推理回放只读取合法的 `Items` 项目列表。旧单密文记录等同没有可用回放，不重新封装、不删除；新请求产生有效回放后按现有所有权和 TTL 保存。当前请求携带的合法加密推理项目继续支持。需要完整上下文时由客户端重新发送历史或开启新会话，不依赖退役记录恢复推理证明。
- 退役的全局模型索引不再查询或维护，其 Redis 字节保留。推理及模型目录必须指定四渠道之一，使用 `/{provider}` 或 `/{provider}/v1`；渠道索引仍支持损坏扫描修复，精确模型和推理档位变体仍可使用。

工具名称及 JSON 参数按标准协议原样交付。网关不再补写文件工具成功文案，也不会把被拒绝的文件正文转为普通文本；真正空输出使用通用失败与重试流程。

Responses 创建、Chat 转换、结果投影及渠道压缩桥接由 `internal/responses` 负责；Grok 保留 Build 原生处理、私有搜索和账号会话。HTTP/2 指纹传输的弃用接口迁移另行处理，本次保持行为。
